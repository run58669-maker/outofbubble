## Overview page — "What to Submit"

```
- Can an agent support people in rare-disease journeys by finding the right mix of information + community + next steps that matches what they actually need both emotionally and practically?
What to Submit
To be eligible, your submission must include all of the following:
1. A link to a functional demo application
A live, working app participants can try end-to-end. This should demonstrate the core features of your project.
2. A URL to a public code repository (GitHub, GitLab, or Bitbucket)
The repo must be public and it should contain all source code, assets, and instructions needed for the project to run.
3. A text description of what your project does
Explain the key features and functionality: what the agent or workflow can do, and what makes it "Qloo-powered."
4. External hosting / fully published requirement
Your demo must be hosted and fully published externally, such as a live website or web app, or a hosted APK / TestFlight build. Submissions that only run locally or rely on private access will not qualify.
5. An open-source license, with the file visible in About section of your repo.
```

## Official rules — "Submission Requirements" and "Testing"

```
1. Dates and Timing
Registration and Submission Period: September 30, 2026 (9:00 am Eastern Time) – October 30, 2026 (11:45 pm Eastern Time) (“Registration & Submission Period ”).
Submission Requirements
Submissions to the Hackathon must meet the following requirements:
Include a Project built with the required developer tools and meets the above Project Requirements.
Provide a link to a functional demo application
Provide a URL to your public code repository for judging and testing on either GitHub, GitLab or Bitbucket. The repository must contain all necessary source code, assets, and instructions required for the project to be functional. The repository must be public and open source by including an open source license file. This license should be detectable and visible at the top of the repository page (in the About section).
Include a text description that should explain the features and functionality of your Project.
Testing
Access must be provided to an Entrant’s working Project for judging and testing by providing a link to a website, functioning demo, or a test build. If Entrant’s website is private, Entrant must include login credentials in its testing instructions. The Entrant must make the Project available free of charge and without any restriction, for testing, evaluation and use by the Sponsor, Administrator and Judges until the Judging Period ends. Judges are not required to test the Project and may choose to judge based solely on the text description, images, and video provided in the Submission.
```

Note: the rules' Testing clause says judges "may choose to judge based solely on the text description, images, and video provided" — a video is optional, but screenshots and a strong text description matter.
